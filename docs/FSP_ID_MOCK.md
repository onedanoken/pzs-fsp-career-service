# Изолированная проверка ФСП ID

Выпуск 0.16.0 содержит OIDC-клиент и отдельный **протокольный mock** с URL-схемой Keycloak. Доступ к официальному ФСП ID не предоставлен. Обычная регистрация и вход в сервис сохраняются; привязка начинается из собственного кабинета кандидата. [Контракт](FSP_CONTRACT.md).

## Запуск отдельного стенда

Используйте отдельный каталог и новые тома PostgreSQL. В приватном `.env` задайте новый `FSP_POSTGRES_PASSWORD`, параметры тестовой почты и `FSP_MOCK_ACCOUNT_PASSWORD` не короче 12 символов:

```sh
docker compose --env-file .env -p fsp-oidc-review -f compose.yaml -f deploy/compose.fsp-id-mock.yaml up --build -d
```

Приложение — `http://localhost:8000`, провайдер — `http://127.0.0.1:17771/realms/fsp`. Mock не использует рабочую БД, SQLite, реальные аккаунты Федерации или пользовательские пароли основного экземпляра. Для нового кандидата требуется email-подтверждение тестовым транспортом либо подготовленный оператором username-аккаунт в этом отдельном контуре.

Войдите кандидатом, откройте ФСП ID и начните привязку через провайдера. В mock используются `fsp-test-001` либо `fsp-test-002` и установленный оператором тестовый пароль. Браузер вернётся в кабинет; идентичность имеет явно тестовый источник. Ввод номера без этого процесса остаётся неподтверждённым запросом.

## Что проверяет протокол

Discovery и JWKS расположены под `/realms/fsp`, а Authorization Code — под `/realms/fsp/protocol/openid-connect/`. Проверяются клиент, зарегистрированный redirect, PKCE S256, одноразовый код, сроки, state/nonce, RS256, issuer и audience.

Запрос входа внутри mock живёт 5 минут; пять неправильных паролей прекращают его. OAuth-код живёт 60 секунд и применяется один раз. Отдельное состояние OIDC-клиента приложения живёт 10 минут. Ключ подписи и коды находятся в памяти mock и теряются при перезапуске — это свойство протокольного стенда, а не промышленного управления идентичностями.

`FSP_OIDC_BACKCHANNEL_BASE` допускается только при явном тестовом режиме для ограниченных внутренних адресов, чтобы контейнер приложения обращался к mock. Обычная интеграция использует HTTPS без такой подмены адреса. Маркер `fsp_mock` в проверенном discovery или токене и `FSP_OIDC_DEMO_ISSUER=1` не позволяют назвать mock официальным подтверждением.

`scripts/mock_fsp_id.py`, `tests/test_reference_oidc.py` и браузерные проверки подтверждают криптографические и пользовательские переходы. Условия — в [VERIFICATION.md](VERIFICATION.md), общая установка — в [INSTALLATION.md](INSTALLATION.md).

Mock не является установленным общим Keycloak, не создаёт настоящих аккаунтов ФСП и не подтверждает спортивную или профессиональную квалификацию. Для реального провайдера потребуются его согласованные metadata, зарегистрированный клиент, claim участника и проверка разрешённого обмена.
